# Codex 답 형식 확인

리뷰 뒤 Codex가 계획을 고쳐 Claude를 부르는 흐름을 만들기 전에, Codex가 AI 메시지 형식(ai-msg v1, AGENTS.md "AI 메시지 형식")으로 답할 수 있는지 실제 PR에서 확인한다. 확인 PR에는 `ai:` 라벨이 없으므로 Codex 답이 형식에 맞아도 자동 흐름은 돌지 않는다.

## 확인할 것

| 항목 | 기준 |
|---|---|
| 표시 줄 | 댓글 원문의 첫 줄(멘션이 있으면 둘째 줄)에 `<!-- ai-msg:v1 ... -->`가 그대로 남는다 |
| 멘션 | `change`는 첫 줄이 `@claude` 한 단어다 |
| 절 | 필수 절이 `### 절 이름`으로 빠짐없이 있고 다른 글이 앞에 없다 |
| 덧붙는 글 | Codex가 끝에 붙이는 `View task →` 같은 줄이 검사를 깨는지 |
| 역할 | 코드를 고치거나 커밋하지 않고 댓글만 단다 |
| 검사 결과 | `scripts/ai/ai-msg.js`의 `validateMessage` 결과 |

## 요청

PR에 메인테이너 계정으로 아래 세 댓글을 하나씩 달고, 앞의 답이 온 뒤 다음을 단다.

1. `change`, 형식을 요청에 적어 줌
2. `answer`, 형식을 요청에 적어 줌
3. `change`, 형식을 적지 않고 AGENTS.md만 따르게 함(실제 자동 요청과 같은 조건)

## 결론

1. 틀을 적어 주면 Codex는 표시 줄, 멘션, 절, `reply-to`(요청 댓글 ID)까지 정확히 지킨다. HTML 주석인 표시 줄도 그대로 남는다.
2. 틀 없이 AGENTS.md만 따르라고 하면 지키지 않는다. AGENTS.md "PR 수정 요청 (Codex)"이 "코드를 바꾸지 않는다"고 하는데도 코드를 고쳐 커밋했다. 따라서 워크플로가 Codex에게 보내는 요청(`ai-relay` 질문 요청, 리뷰 뒤 정리 요청)과 사용자 수정 요청 안내에는 채워진 틀을 넣어야 한다. 지금 `relayRequestBody`는 틀 없이 AGENTS.md를 가리키기만 하므로 고쳐야 한다.
3. Codex는 작업 결과 끝에 ` [View task →](…)` 줄을 항상 붙인다. 지금 파서는 이 줄을 마지막 절의 내용으로 읽는다. 그래서 `answer`의 `### 재시작`처럼 값이 정해진 절이 마지막에 오면 형식 오류가 된다. 실제 흐름에서는 모든 `answer`가 거절되므로, 파서가 끝의 View task 줄을 떼고 읽어야 한다.
4. #136의 코드 수정 판별 문구에 이번 답("커밋으로 저장했습니다", "후속 Pull Request를 생성했습니다")이 맞지 않아 `other`로 분류됐다. 코드 수정을 놓치면 게이트는 그 댓글을 리뷰로도 세지 않으므로 통과시키지는 않는다. 하지만 자동 흐름은 멈추지 않고 사용자도 알림을 받지 못한다. 문구 하나하나 대신 "커밋 SHA와 커밋이라는 말이 함께 있음", "PR을 만들었다는 말"처럼 넓은 기준이 필요하다.
5. 리뷰 뒤 Codex가 계획을 고쳐 Claude를 부르는 흐름은 2~4를 고치면 만들 수 있다. 정리 요청에는 채워진 `change` 틀과 "P0/P1은 무시할 수 없다"는 규칙을 넣는다.
