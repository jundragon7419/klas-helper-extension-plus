# 자동 흐름 측정 기록

Claude와 Codex 자동 흐름([협업 규칙](AI-COLLABORATION.md))이 실제로 사람의 일을 줄였는지 판단하기 위한 기록입니다. 자동 흐름으로 진행한 기능 이슈를 머지할 때마다 한 행을 더합니다.

## 기록하는 법

1. 이슈를 닫은 PR이 머지되면 저장소 폴더에서 실행합니다. `gh` CLI 로그인이 필요합니다.

   ```shell
   npm run ai:metrics -- <이슈 번호>
   ```

2. 출력된 행을 아래 "정비 후" 표 맨 아래에 붙입니다.
3. "머지 뒤 버그" 칸은 직접 채웁니다. 처음에는 비워 두고, 이 기능 때문에 생긴 버그 이슈가 생기면 번호를 적습니다. 머지하고 2주가 지나도 없으면 `없음`을 적습니다.

계산은 `scripts/ai/metrics.js`가 GitHub 기록(댓글, 라벨 이벤트, 리뷰 댓글)으로 합니다.

## 항목

| 항목 | 뜻 | 계산 |
|---|---|---|
| 생성→머지 | 이슈를 만든 때부터 PR 머지까지 | 이슈 생성 시각과 PR 머지 시각의 차이 |
| 사람 대기 | 자동 흐름이 사람을 기다린 시간 | 이슈와 PR에 `ai:needs-human`이 붙어 있던 기간 + 마지막 `ai:ready`부터 머지까지 |
| start | 구현을 시작시킨 횟수 | 이슈에 메인테이너가 단 `@claude` 댓글(`start` 메시지 포함) 수. 1이 정상이고, 더 많으면 다시 시작한 것이다 |
| 멈춤 | 자동 흐름이 멈춘 횟수 | 이슈와 PR에 `ai:needs-human`이 붙은 횟수 |
| ask | Claude가 막혀서 물은 횟수 | 이슈와 PR의 Claude `ask`, `objection` 메시지 수 |
| need-user | Codex가 답하지 못해 사용자에게 넘긴 횟수 | Codex `need-user` 메시지 수 |
| 지적 / 반영 | Codex 지적 수와 그중 고친 수 | PR의 Codex 줄 단위 리뷰 댓글 수 / 그중 지적이 달린 커밋 뒤에 새 커밋이 올라온 수 |
| 머지 뒤 버그 | 이 기능 때문에 생긴 버그 | 직접 적는다 |

- `ask`와 `need-user`는 메시지 형식(ai-msg v1, #127)을 도입한 뒤에만 셀 수 있습니다. 그 전 이슈는 0으로 나오므로 "멈춤"으로 비교합니다.
- "반영"은 지적이 달린 커밋 다음에 고친 커밋이 있었는지로 셉니다. 고친 커밋이 그 지적을 실제로 다뤘는지는 보지 않습니다.
- 사람이 KLAS 화면을 확인하는 시간처럼 GitHub 기록에 남지 않는 시간은 들어가지 않습니다.
