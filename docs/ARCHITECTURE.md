# 구조와 결정 사항

## 목표

KLAS를 보고 있을 때 돕는 확장을 만든다. KLAS 화면 오른쪽의 탭에서 마감 일정 같은 정보를 모아 보여 주고, 기존 KLAS 화면에는 그 페이지에서만 의미 있는 기능을 더한다. KLAS가 열려 있지 않을 때는 KLAS에 요청하지 않는다.

## 기존 KLAS Helper와 다른 점

기존 확장은 `app.js`를 `<script>` 태그로 KLAS 페이지(페이지 world)에 넣고, KLAS의 axios와 Vue 인스턴스(`appModule`)를 빌려 써서 화면을 바꾼다. 이 방식은 KLAS가 프론트엔드를 조금만 바꿔도 여러 기능이 같이 깨진다.

이 프로젝트는 KLAS 내부 API를 확장이 직접 호출하고, 정보를 모아 보는 화면은 KLAS 레이아웃과 분리된 탭에 그린다. 기존 KLAS 화면에 넣는 기능은 기능마다 독립된 모듈로 만들어, KLAS가 바뀌어도 해당 기능 하나만 멈추게 한다.

## 구성

```
KLAS 페이지 (content script)                 background
  ├─ KLAS 탭: 오른쪽 가운데 < 버튼으로 여닫음     ├─ 캐시: chrome.storage
  │    마감 일정 등 (Shadow DOM, Preact)          ├─ 탭 사이 조정: 여러 KLAS 탭 중 한 곳만 조회
  ├─ KLAS API 조회 ───────── 저장 ──────────▶   └─ 세션 연장 타이머: chrome.alarms 10분
  ├─ 세션 연장 요청 ◀──── KLAS 탭이 있을 때만 ──────┘
  └─ 기존 화면 기능 모듈 (페이지별, 기능마다 독립)

(선택) MAIN world 스크립트: KLAS 동작을 꼭 바꿔야 할 때만, 로직 없이
```

### 원칙

1. KLAS가 열려 있지 않으면 KLAS에 요청하지 않는다. 조회와 세션 연장은 모두 KLAS 탭이 있을 때만 한다.
2. KLAS 요청은 KLAS 탭의 content script가 보낸다. KLAS와 같은 출처에서 요청하므로 브라우저의 서드파티 쿠키 설정이나 추적 방지의 영향을 받지 않는다.
3. background는 캐시, 탭 사이 조정, 세션 연장 타이머를 맡는다. 탭이 여러 개여도 같은 조회가 겹치지 않게 하고, 최근 결과가 있으면 다시 요청하지 않는다.
4. 세션은 KLAS 탭이 열려 있는 동안 10분마다 연장하고, 설정으로 끌 수 있다. content script 안의 타이머는 뒤에 숨은 탭에서 느려지므로 background의 alarms가 시점을 정한다.
5. service worker는 쉬고 있으면 종료된다. 상태는 변수가 아니라 `chrome.storage`에 둔다.
6. 화면은 캐시를 먼저 보여 주고 뒤에서 새로 고친다. 언제 기준의 정보인지 표시한다.
7. 기존 KLAS 화면에 넣는 기능은 기능마다 독립된 모듈로 만들고, 넣을 위치를 찾지 못하면 그 기능만 꺼진다.
8. 기존 KLAS 화면에 넣거나 바꾼 요소에는 확장 표시를 붙이고, 원래 요소를 말없이 지우지 않는다.
9. MAIN world 스크립트는 최소한으로 둔다. 필요한 정보는 `CustomEvent`로 content script와 주고받는다.
10. 권한은 기능에 필요한 만큼만 요청한다.

## 화면

### 방식: KLAS 안의 탭

2026-11-06에 결정했다. 이슈 #7에서 정한 "툴바 배지 + 브라우저 사이드 패널"을 대체한다.

- **열고 닫기**: KLAS 화면 오른쪽 가운데에 살짝 튀어나온 `<` 버튼을 누르면 탭이 오른쪽에서 밀려 나오고, 다시 누르면 들어간다.
- **그리는 방법**: content script가 `body`에 고정 위치로 붙이고 Shadow DOM 안에 그린다. KLAS 레이아웃이나 CSS가 바뀌어도 영향을 거의 받지 않는다.
- **첫 목표**: 탭에 마감 일정만 보여 준다. 다른 기능은 v0.1.0을 써 본 뒤 정한다.
- **브라우저 사이드 패널을 쓰지 않는 이유**
  - 툴바 아이콘을 눌러야 열려서, 확장 아이콘을 숨겨 둔 사용자는 있는 줄 모를 수 있다. KLAS 안의 탭은 KLAS 화면에 항상 보인다.
  - Chrome과 Edge의 `sidePanel`, Firefox의 `sidebar_action`을 따로 처리할 필요 없이 세 브라우저가 같은 코드를 쓴다. `sidePanel` 권한도 필요 없다.
  - 조회와 화면이 같은 content script 안에 있어서 메시지를 주고받을 필요가 없다.
- **단점**: 탭을 열면 KLAS 화면 일부를 가린다. 폭과 좁은 창에서의 동작은 아래 "KLAS 탭 디자인"에 정했다.

### KLAS 탭 디자인 (#25)

2026-11-06에 정했다. 시안은 `docs/design/`에 있다.

- **색**: 파란색 대신 KLAS가 쓰는 색을 쓴다. 값은 2026-11-06에 KLAS `style.css`에서 읽었다.
  - 브랜드 바: KLAS 상단 바 `#3a051f` (`.bg-top`), 보조 글자 `#afa5a9` (`.navtxt`)
  - 강조: `#b10058` (KLAS 탭 `.defaulttabs`, 버튼 `.btn-learn`), 마우스를 올렸을 때 `#8f0047`
  - 글자 `#222222`, 보조 글자 `#666666`, 표 테두리 `#dddddd`, 표 머리 바탕 `#f5f5f5`
  - 글꼴과 굵기도 KLAS를 따른다: `"Noto Sans KR", "Malgun Gothic", sans-serif`, 본문 14px, 굵기 300. Noto Sans KR은 KLAS 페이지가 이미 불러오므로 확장에 넣지 않는다.
- **탭 구조**: 맨 위에 "KLAS Helper+" 브랜드 바(48px, 설정과 닫기 버튼), 그 아래 탭 줄을 둔다. 탭 줄은 KLAS `.defaulttabs`와 같은 모양이다(아래 선 `#dee2e6`, 선택된 탭은 `#b10058` 글자와 2px 밑줄). 첫 탭은 "마감 일정"이고, 다른 탭은 기능이 생길 때 더한다.
- **탭 내용**: 목록과 상태 화면은 아래 "마감 일정 탭 내용"을 따른다.
- **손잡이**: 화면 오른쪽 세로 가운데에 28×72px 버튼을 붙인다(강조색 바탕). 마우스를 올리거나 키보드로 포커스하면 40px로 넓어진다. 화면 맨 위 KLAS 메뉴는 가리지 않는다. 탭을 열면 패널 왼쪽 가장자리로 이동하고, 화살표가 오른쪽을 가리킨다. 손잡이를 다시 누르면 탭을 닫는다.
- **폭**: 360px. KLAS 화면을 어둡게 덮지 않고 오른쪽에 겹쳐 열어서, 연 채로 KLAS를 계속 쓸 수 있다. 브랜드 바의 X 버튼, Esc, 패널 왼쪽의 KLAS 화면 클릭으로 닫는다. X 버튼에 마우스를 올리면 원형 배경이 나타난다. KLAS 화면을 클릭하면 누른 요소는 평소대로 동작한다.
- **좁은 창**: 창 폭이 480px보다 좁으면 탭이 화면 전체를 덮는다. 손잡이는 패널 왼쪽 안쪽에 둔다. 패널이 열려 있으면 Tab과 Shift+Tab은 손잡이와 패널 안의 조작 요소 사이에서 순환한다. 키보드나 닫기 버튼으로 닫으면 포커스를 손잡이로 돌려준다. 480px 이상에서는 KLAS 화면도 기본 Tab 순서에 포함된다.
- **접근성**: 아이콘만 있는 버튼에는 `aria-label`을 붙이고 누를 수 있는 크기를 44px 이상으로 한다. 탭 줄은 `role="tablist"`와 `role="tab"`을 쓴다.
- **디자인 토큰**: 색, 글자, 간격, 모서리, 크기, 그림자, 움직임 값은 `utils/ui/tokens.ts` 한 곳에 둔다.
  - `tokensToCss()`가 `--khp-` CSS 변수로 바꿔 shadow root 맨 앞에 넣는다.
  - `:host`에 `all: initial`을 먼저 넣어 KLAS에서 상속되는 글꼴, 색, 줄 높이를 끊는다.
  - 글자 크기는 px로 둔다. shadow root 안에서도 rem은 KLAS 문서의 html 글자 크기를 따르기 때문이다.
  - 컴포넌트는 hex 값 대신 쓰임새 이름(`text-muted`, `accent` 등)만 쓴다. 다크 모드를 넣을 때 값만 바꾸면 된다.
  - 글자색과 바탕색 짝을 `CONTRAST_PAIRS`에 적고, `tests/tokens.test.ts`가 글자 4.5:1, 글자 아닌 요소 3:1 이상인지 검사한다.
  - `npm run tokens:preview`로 미리보기 페이지를 연다. 값을 바꿔 보며 견본과 대비를 확인하고, "tokens.ts에 저장"을 누르면 개발 서버가 `tokens.ts`의 값 구간만 다시 쓴다. 이름을 더하거나 지우는 일은 파일을 직접 고친다.
- **다크 모드**: v0.1.0은 밝은 화면만 만든다. KLAS가 밝은 화면만 있기 때문이다. 다크 시안은 남겨 두고, v0.1.0 뒤에 운영체제 설정(`prefers-color-scheme`)을 따르게 추가할지 정한다.
- **확장 아이콘**: 시안의 "달력 +"를 임시로 쓴다. 정식 아이콘은 나중에 따로 디자인한다.
- **아직 정하지 않은 것**: 손잡이에 24시간 안 마감 수를 붙일지, 탭을 여는 단축키를 둘지.

#### 마감 일정 탭 내용 (#40)

- `pendingDeadlines`로 완료했거나 지난 항목을 거른다. 남은 항목은 한국 시간(`Asia/Seoul`)의 마감 날짜별로 묶고, 날짜와 각 묶음 안의 항목을 마감이 빠른 순으로 보여 준다. 묶음 제목에는 날짜, 요일, 표시한 항목 수를 적는다.
- 항목에는 종류(강의, 과제, 팀 프로젝트, 퀴즈), 과목, 제목, 마감 시각 순으로 적는다. 마감 시각은 한국 시간 24시간제로 표시한다. 오른쪽에 `formatRemaining`으로 계산한 남은 시간을 표시하고, 24시간 미만이면 강조한다. 추가 제출 기한을 적용한 항목(`extended`)의 마감 시각 옆에는 “연장 기간”을 붙인다.
- 항목 전체를 눌러 같은 탭에서 해당 학기와 과목의 KLAS 목록(`listPage`)으로 이동한다. MAIN world의 이동 스크립트가 목록 경로를 검사한 뒤 KLAS의 `appModule.goLctrumBoard`로 이동한다. 해당 함수가 없는 과목 화면에서는 KLAS 공통 함수 `setLctrumInfo`로 선택 학기와 과목을 갱신한 뒤 `linkUrl`로 같은 탭에서 이동한다. KLAS는 목록을 열 때 POST 필드보다 브라우저에 저장한 선택을 먼저 쓴다. 이동은 목록 페이지까지로 한다.
- 탭 줄 아래에 “마지막 확인” 시각과 새로고침 아이콘 버튼(접근 가능한 이름 “다시 확인”)을 둔다. 시각은 표시 중인 결과의 `checkedAt`을 한국 시간으로 표시하고, 결과가 없으면 “아직 확인한 기록이 없습니다”라고 적는다. “다시 확인”은 최근 캐시의 재사용을 건너뛰되, 다른 탭이 조회 중이면 기다린다. 조회 중에는 버튼의 포커스를 유지하고 다시 실행할 수 없게 한다.

아래 표를 위에서부터 적용한다. 결과는 확인한 계정과 일치하는 캐시에서 가져온다. 계정을 확인할 수 없으면 목록을 표시하지 않는다.

| 조건 | 표시 |
|---|---|
| 로그인 화면이거나 최근 조회 오류(`lastError`)가 `session` | “KLAS 로그인이 필요합니다”. 이전 목록을 숨기고 “KLAS 로그인 화면으로” 링크를 표시한다. |
| 조회 중 또는 다른 탭의 조회를 기다리는 중 | “마감 일정을 확인하는 중입니다”. 같은 계정의 이전 목록이 있으면 마지막 확인 시각과 함께 표시한다. |
| 로그인 만료 외의 조회 실패, 표시할 이전 결과 있음 | “새로 확인하지 못했습니다. 저장된 목록을 보여 줍니다”. 이전 결과에서 아직 남은 항목을 표시한다. 항목이 없어도 이 안내를 유지한다. |
| 로그인 만료 외의 조회 실패, 표시할 이전 결과 없음 | “마감 일정을 확인하지 못했습니다”. `unexpected`도 이 상태로 처리하며, 내부 오류 문자열은 화면에 표시하지 않는다. |
| 조회 결과에 `failures` 또는 `skipped`가 있음 | “일부 마감을 확인하지 못했습니다”. 확인한 항목만 표시한다. 표시할 항목이 0개여도 안내를 유지한다. |
| 조회가 끝났고 표시할 결과가 아직 없음 | “아직 확인한 기록이 없습니다”. |
| 누락 없이 확인했고 남은 항목이 0개 | “남은 마감이 없습니다”. |
| 누락 없이 확인했고 남은 항목이 있음 | 날짜별 목록을 표시한다. |

### 기능 배치

- **KLAS 탭에 넣을 것**: 어느 KLAS 페이지에서든 따로 떼어 볼 수 있는 정보 (마감 일정, 성적 평점, 석차, 어학 성적, 강의 새 글, 바로가기, 설정)
- **기존 KLAS 화면에 넣을 것**: 그 페이지에서만 의미 있는 기능 (시간표 시간 표시, 강의 숨기기, 강의계획서 검색 편의 등)
- 어떤 기능을 v1.0에 넣을지는 `docs/ROADMAP.md`를 따른다.

### 확장 표시

- 기존 KLAS 화면에 넣거나 바꾼 메뉴, 버튼, 문구에는 확장 기능이라는 표시를 붙인다. 사용자가 KLAS 원래 기능과 확장 기능을 구분할 수 있게 하고, 문제가 생겼을 때 어디에 알려야 하는지 알 수 있게 하기 위해서다.
- **KLAS 안에 넣는 요소는 KLAS와 똑같이 보여야 한다.** shadow root를 쓰지 않고 KLAS와 같은 마크업과 클래스로 넣어 KLAS CSS가 그리게 한다. 확장이 더하는 스타일은 `+` 표시 하나뿐이다.
  - 예: 햄버거 메뉴에 넣는 항목은 KLAS 메뉴의 `.depth03ul > li > a`로 넣는다. KLAS CSS가 앞에 "-"를 그리므로 "- 마감 일정+"처럼 보인다.
- 표시 모양은 요소 바로 뒤에 붙는 작은 위첨자 `+`다 (#25에서 결정). 밝은 바탕에서는 KLAS 강조색 `#b10058`, KLAS 상단 바 위에서는 KLAS 주황 `#f29d0c`로 하고, 하나의 공통 부품으로 만든다. `+` 글자는 `aria-hidden`으로 숨기고 화면 낭독기용 글을 따로 붙인다. 마우스를 올리면 같은 글을 `title`로 보여 준다.
- 화면 낭독기가 "KLAS Helper+ 기능"이라고 읽도록 설명을 붙인다.
- 시간표 칸처럼 반복되는 요소는 칸마다 붙이지 않고 영역 제목에 한 번만 붙인다.
- KLAS 탭 자체는 확장 화면이라 따로 표시하지 않는다.

### UI 프레임워크: Preact

이슈 #7에서 정했다. 사이드 패널 대신 KLAS 탭의 Shadow DOM 안에 그리는 것으로 바뀌었지만 결정은 그대로다.

시안 A의 마감 목록(필터 버튼 5개, 항목 6개)을 같은 내용으로 네 번 만들어 운영 빌드한 결과:

| 방식 | JS 크기 | gzip 후 | 추가 설정 | 타입 검사, lint |
|---|---|---|---|---|
| 프레임워크 없음 | 2.4 KB | 1.1 KB | 없음 | 그대로 통과 |
| Preact 11 | 15 KB | 6.4 KB | Vite 플러그인, tsconfig 2줄 | 그대로 통과 |
| Svelte 5 | 35 KB | 13.8 KB | WXT 모듈 | `.svelte`는 `tsc`, ESLint로 검사되지 않아 `svelte-check`와 ESLint 플러그인이 더 필요 |
| React 19 | 221 KB | 68 KB | WXT 모듈, tsconfig 1줄 | 그대로 통과 |

Preact를 고른 이유:

- React와 문법이 같아서 React를 아는 기여자가 바로 참여할 수 있다.
- 크기가 React의 10분의 1이다. content script는 KLAS 페이지를 열 때마다 로드되므로 가벼운 편이 낫다.
- 지금의 검사 체계(`tsc`, ESLint, Vitest)를 그대로 쓴다.
- 프레임워크 없이 만들면 같은 화면에서도 DOM을 직접 다루는 코드가 길어져서, 화면이 늘어날수록 읽기 어려워진다.

설정할 때 필요한 것: `@preact/preset-vite`를 `wxt.config.ts`의 Vite 플러그인에 추가하고, `tsconfig.json`에 `"jsx": "react-jsx"`, `"jsxImportSource": "preact"`를 넣는다. hooks 규칙을 검사하려면 `eslint-plugin-react-hooks`를 함께 쓴다.

## 검증된 사실 (2026-11-05, Chrome, 테스트 확장으로 확인)

- KLAS의 axios나 Vue 없이 `fetch`만으로 아래 API를 조회할 수 있다. CSRF 토큰이나 별도 헤더는 필요 없다.
- 확장 페이지, background(service worker), content script(격리 world) 세 곳 모두에서 로그인 쿠키가 실리고 같은 결과가 나왔다.
- Firefox 159에서도 content script의 기본 `fetch`로 같은 결과가 나왔다. 로그인 쿠키가 실리고 JSON이 온다. 향상된 추적 방지를 "표준"과 "엄격"으로 둔 경우 모두 같았다. Chrome과 같은 코드를 쓴다. (2026-11-06, 임시 부가 기능으로 확인, #17)
  - Firefox 전용이던 `content.fetch`는 Firefox 159에 없다.
  - 페이지 world의 `fetch`(`window.wrappedJSObject.fetch`)도 동작한다. 기본 `fetch`가 막힐 때의 예비 수단이다.
  - 임시 부가 기능으로 올렸을 때 `klas.kw.ac.kr` 사이트 권한은 처음부터 허용되어 있었다.
- KLAS의 기본 세션 시간은 2시간(7200초)이다. 아무것도 하지 않으면 그 뒤에 로그아웃된다. 서버 값으로 확인했다. (2026-11-06, #16)
- 원래 KLAS Helper는 사이트를 다시 불러오거나(10분마다) KLAS의 세션 연장 함수를 호출해서(5분마다) 세션을 유지해 왔다. (kw-service/klas-helper-userscript PR #30, 이슈 #99, kw-service/klas-helper-extension PR #17)

## KLAS 내부 API

모두 `POST`, 본문은 JSON이다.

| 용도 | 경로 | 본문 |
|---|---|---|
| 학기별 수강 과목 | `/std/cmn/frame/YearhakgiAtnlcSbjectList.do` | `{}` |
| 온라인 강의 | `/std/lis/evltn/SelectOnlineCntntsStdList.do` | 과목 공통 본문 |
| 과제 | `/std/lis/evltn/TaskStdList.do` | 과목 공통 본문 |
| 팀 프로젝트 | `/std/lis/evltn/PrjctStdList.do` | 과목 공통 본문 |
| 퀴즈 | `/std/lis/evltn/AnytmQuizStdList.do` | 과목 공통 본문 |

과목 공통 본문: `{"selectSubj": <과목 value>, "selectYearhakgi": <학기 value>, "selectChangeYn": "Y"}`

수강 과목 응답 형태:

```json
[{ "value": "2026,2", "label": "2026년도 2학기", "subjList": [{ "value": "<과목 코드>", "label": "...", "name": "<과목명>" }] }]
```

### 주의할 점

- **본문은 반드시 JSON.** `Content-Type: application/json`으로 보낸다. form 형식(`x-www-form-urlencoded`)으로 보내면 HTTP 500이 난다.
- **세션이 끊겨도 HTTP 200이다.** 로그인 페이지 HTML이 리다이렉트로 온다. 성공 여부는 상태 코드가 아니라 `content-type`이 JSON인지로 판단한다.
- **잘못된 요청에도 빈 배열이 온다.** 과목 코드 필드를 잘못 넣어도 에러 없이 `[]`가 온다. 응답 스키마 검사와 테스트로 막는다.
- **과목 코드는 `subj`가 아니라 `value` 필드다.**

### 조회 코드

`utils/klas/api.ts`가 다섯 API를 부르고 `utils/klas/schema.ts`가 응답을 검사한다. 결과는 성공 또는 실패이고, 실패는 다섯 종류로 나눈다.

| 종류 | 뜻 | 판단 |
|---|---|---|
| `session` | 로그인이 끊김 | 응답 주소가 `/usr/cmn/login/LoginForm.do` (로그인 페이지로 이동). `UpdateSession.do`도 `/usr/cmn/login/` 아래에 있으므로 경로 전체로 판단하지 않는다 |
| `network` | 요청 실패 | 요청 예외, 시간 초과(15초), HTTP 오류 |
| `not-json` | 알 수 없는 응답 | 로그인 페이지가 아니고 `content-type`이 JSON이 아니거나 JSON을 읽을 수 없음 |
| `schema` | KLAS 형식 바뀜 | JSON이지만 쓰는 필드가 없거나 형식이 다름 |
| `unexpected` | 확장 오류 | 조회 도중 확장 코드에서 예외가 남. KLAS 요청이 아니라 확장 버그다 (#41) |

응답 검사는 확장이 쓰는 필드만 확인한다. 필드가 더해지는 것은 괜찮다. 온라인 강의 목록에는 강의(`evltnSe: "lesson"`)와 퀴즈(`"quiz"`)가 섞여 오고, 퀴즈 줄에는 `isonoff`, `prog`가 없다.


### 조회 조정과 캐시 (#23)

KLAS 페이지가 열릴 때마다 content script가 background에 조회해도 되는지 묻는다. 여러 KLAS 탭이 열려 있어도 조회는 한 탭만 한다.

| background의 답 | 조건 | content script가 하는 일 |
|---|---|---|
| `fetch` | 최근 결과가 없고 다른 탭이 조회 중이 아님 | 조회권을 받아 현재 학기 과목을 모두 조회하고 결과를 알린다 |
| `wait` | 다른 탭이 조회 중 (새로 고침이어도 마찬가지) | 캐시가 바뀌기를 기다린다 |
| `use-cache` | 5분 안에 성공한 결과가 있거나, 1분 안에 실패함 | 캐시를 쓴다 |

- 조회 한 번은 과목 목록 1번과 과목 수 × 4번이다. 과목 하나의 네 목록은 동시에, 과목은 차례로 부른다.
- 캐시는 `storage.local`의 `deadlineCache`에 둔다. 마지막으로 성공한 결과와 마지막 실패를 담는다. 실패해도 이전 결과는 남긴다. KLAS 홈 응답의 상단 내 정보 링크에서 학번을 읽고 SHA-256 해시만 캐시에 저장한다. 계정이 바뀌면 캐시와 기존 조회권을 비운다. 계정을 확인할 수 없으면 캐시를 읽거나 쓰지 않고 조회 상태만 표시한다. 조회 결과를 저장하기 전 계정을 다시 확인한다. 조회 중인 탭이 다른 계정을 확인하면 기존 계정의 캐시를 비운다. 로그아웃 화면에서는 캐시를 지우지 않으며, 다음에 로그인한 계정이 다를 때 지운다.
- 조회권은 `storage.session`의 `fetchLease`에 둔다. 조회 중인 탭이 닫히면 바로 돌려받고, 응답 없이 멈추면 3분 뒤 만료되어 다음에 묻는 탭이 이어받는다. 요청 하나의 제한 시간이 15초라서 과목 10개까지 모두 제한 시간을 채워도(15초 × 11) 조회 도중에 만료되지 않는 길이다 (#41). 계정이 전환될 때마다 조회권의 범위를 바꾼다. 같은 계정으로 돌아와도 전환 전 조회권으로 받은 결과는 버린다. 같은 범위에서 조회권이 바뀐 뒤 도착한 성공 결과는 캐시가 비어 있거나 저장된 결과보다 조회 시작 시각(`checkedAt`)이 늦을 때만 저장한다. 뒤늦게 도착한 실패는 버린다. 성공 결과로 목록을 갱신하더라도, 조회 시작 시각이 마지막 실패 기록 시각보다 늦을 때만 실패 기록을 지운다 (#56).
- 조회 함수에서 예외가 나도 `unexpected` 실패로 알려서, 조회권을 바로 돌려주고 실패를 캐시에 남긴다 (#41).
- 실패 뒤 1분은 다시 조회하지 않는다. 세션 만료는 예외로, 다시 로그인하면 바로 조회한다.
- 조회 도중 로그인이 끊기거나 모든 마감 목록의 조회가 실패하면 전체를 실패로 보고 이전 결과를 유지한다. 조회할 과목이 없거나 조회에 성공한 목록이 비어 있는 경우는 정상으로 처리한다. 그 밖의 이유로 일부 목록이 실패하면 나머지 마감은 저장하고 실패한 목록을 `failures`에 남긴다.
- background는 메시지를 한 번에 하나씩 처리해서, 동시에 물은 탭들이 조회권을 함께 받지 않게 한다.

### 세션 (2026-11-06, Edge, #16)

KLAS 화면의 남은 시간 표시는 서버의 `GET /api/v1/session/info`에서 값을 받는다. 응답 예: `{"remainingTime": 7126, "sessionNotiSec": 6826, "logoutCountDownSec": 300}`. 남은 시간이 300초가 되면 화면에 연장 안내가 뜨고, 0이 되면 페이지가 `/usr/cmn/login/Logout.do`를 호출한다. 화면은 30초마다 `session/info`를 다시 읽어 서버 값과 10초 넘게 차이 나면 표시를 고친다.

요청마다 `session/info`의 `remainingTime`을 앞뒤로 읽어 비교했다.

| 요청 | 남은 시간 | 응답 |
|---|---|---|
| `GET /api/v1/session/info` | 그대로 줄어듦 (46초 뒤 46초 감소) | JSON |
| `POST /std/cmn/frame/YearhakgiAtnlcSbjectList.do` | 7200으로 되돌아감 | JSON |
| `GET /` | 7200으로 되돌아감 | `Frame.do`로 이동, HTML 약 82 KB |
| `GET /usr/cmn/login/UpdateSession.do` | 7200으로 되돌아감 | JSON `{}` (2 B) |

결정:

- 세션 연장에는 `GET /usr/cmn/login/UpdateSession.do`를 쓴다. KLAS 화면의 연장 버튼이 부르는 요청이고, 응답이 가장 작고, 정보를 읽거나 바꾸지 않는다.
- 세션 상태 확인에는 `GET /api/v1/session/info`를 쓴다. 세션을 연장하지 않으므로, 연장이 꺼져 있을 때도 남은 시간을 읽을 수 있다.
- 일반 API 조회도 세션을 연장한다. 조회 직후에는 따로 연장 요청을 보내지 않아도 된다.
- KLAS 페이지의 세션 연장 함수(`sessionExtensionReq1` 등)는 부르지 않고 요청을 직접 보낸다. 원래 KLAS Helper는 이 함수를 불렀는데, KLAS가 함수 이름을 바꾸자 페이지 스크립트를 뒤져 찾는 방식으로 대응해야 했다 (kw-service/klas-helper-extension PR #17).

### 세션 연장 (#24)

로그인하지 않은 상태에서 확인한 응답 (2026-11-06, 로그인 쿠키 없이 요청):

| 요청 | 응답 |
|---|---|
| `GET /usr/cmn/login/UpdateSession.do` | 200, JSON `{}`. 로그인했을 때와 같아서 이것만으로는 만료를 알 수 없다 |
| `GET /api/v1/session/info` | 500, HTML |
| `POST` 과목 목록 | 200, `LoginForm.do`로 이동 |

연장 순서 (`utils/klas/api.ts`의 `extendSession`):

1. `UpdateSession.do`로 연장한다.
2. `session/info`로 남은 시간을 읽는다. 남은 시간이 있으면 연장된 것이다.
3. 2가 실패했을 때만 과목 목록으로 확인한다. 로그인 페이지로 넘어가면 세션 만료다.

평소 요청은 10분마다 두 번(1, 2)이다.

연장 시점 (`utils/session-keeper.ts`, background):

- KLAS 학생 페이지의 content script가 열렸다고 알리면 그 탭을 `storage.session`의 `klasTabs`에 넣는다. `tabs` 권한 없이 KLAS 탭을 알기 위해서다.
- 첫 탭이 등록되면 10분 주기 알람(`session-keepalive`)을 만든다. 이미 있으면 다시 만들지 않는다. service worker가 깨어날 때마다 새로 만들면 주기가 처음부터 다시 시작되어 알람이 울리지 않을 수 있다.
- KLAS 패널 상단 **설정 → 세션 자동 연장**에서 `sessionKeepAlive`를 변경한다. 기본은 켜짐이며 `storage.local`에 저장한다. 열린 KLAS 탭의 상단 표시와 설정 화면은 저장값 변경을 바로 반영한다.
- 알람이 울리면 연장을 맡기기 전에 설정을 확인한다. 꺼져 있으면 요청하지 않는다. 켜져 있으면 등록된 탭의 content script가 같은 출처로 요청한다.
- 답하지 않는 탭(닫혔거나 KLAS를 벗어남)은 목록에서 빼고 다음 탭에 맡긴다. 탭이 하나도 남지 않으면 알람을 지운다.
- 연장 결과가 세션 만료면 계정 범위가 아직 같을 때 과목 목록으로 현재 로그인을 다시 확인한다. 로그인 페이지가 돌아오고, 계정 범위가 그대로이며, 재확인보다 늦게 시작한 조회가 성공한 적이 없으면 "로그인 필요"를 기록한다. 이전 마감 결과는 남긴다 (#65, #74).

### 날짜 형식

API마다 다르다. 확인한 형식:

| 예시 | 쓰이는 곳 | 해석 |
|---|---|---|
| `2026-12-01 18:00:59` | 과제 `expiredate` | 한국 시간 |
| `2026-11-13T14:59:59.000+00:00` | 팀 프로젝트 `expiredate` | UTC (한국 시간 23:59:59) |
| `2026-10-12 23:59` | 온라인 강의 `endDate`, 퀴즈 `edt` | 한국 시간 |
| `202610122359` | 온라인 강의, 퀴즈 `edate` | 한국 시간 |

`utils/date.ts`의 `parseKlasDate`가 네 형식을 epoch ms로 바꾼다. 시간대 표시가 없는 형식은 PC 시간대와 관계없이 한국 시간(UTC+9)으로 본다. `new Date(문자열)`로 해석하면 PC 시간대를 따라가서 해외에서는 마감이 최대 17시간 어긋나므로 쓰지 않는다. 형식이 다르거나 없는 날짜면 `null`을 돌려준다.

### 마감 판단 규칙 (기존 KLAS Helper `home.js`와 같음)

| 종류 | 대상 | 완료 조건 | 마감 |
|---|---|---|---|
| 온라인 강의 | `evltnSe === "lesson"` 이고 `isonoff !== "OFF"` | `prog === 100` | `endDate` 끝에 `:59` |
| 과제, 팀 프로젝트 | 전부 | `submityn === "Y"` | `expiredate`, 지났으면 `reexpiredate`(추가 제출 기한) |
| 퀴즈 | 전부 | `issubmit === "Y"` | `edt` |

`utils/klas/deadlines.ts`의 `normalizeSubject`가 이 규칙으로 과목 하나의 네 목록을 마감 목록으로 바꾼다. (2026-11-06, #22)

- 온라인 강의 `endDate`는 분 단위(`2026-10-12 23:59`)라서, 그 분의 마지막 초(`23:59:59`)를 마감으로 본다.
- 온라인 강의 목록에 섞여 오는 퀴즈 줄(`evltnSe === "quiz"`)은 퀴즈 목록과 겹치므로 넣지 않는다.
- 과제와 팀 프로젝트는 원래 기한과 추가 제출 기한을 캐시에 보관한다. 화면을 그릴 때 원래 기한이 지났고 `reexpiredate`가 있으면 추가 기한을 마감으로 쓰고 `extended`로 표시한다. 추가 제출 날짜에 값이 있지만 해석할 수 없으면 확인 가능한 원래 기한을 사용하고 일부 마감을 확인하지 못했다고 안내한다. 이전 버전 캐시는 저장된 마감을 보여 주고 다음 조회에서 갱신한다.
- 완료했거나 지난 항목도 목록에 남긴다. 화면에서 무엇을 보일지는 따로 거른다 (`pendingDeadlines`는 하지 않았고 지나지 않은 항목만 마감 순으로 돌려준다).
- 마감 날짜를 읽을 수 없는 항목은 목록에서 빼고 이유를 따로 남긴다.
- 항목 id는 `<종류>:<과목 코드>:<번호>`다. 번호는 강의 `oid`, 과제 `taskNo`, 팀 프로젝트 `ordseq`, 퀴즈 `papernum`이고, 없으면 목록 안의 순서다.
- 항목마다 KLAS 목록 페이지(`OnlineCntntsStdPage.do`, `TaskStdPage.do`, `PrjctStdPage.do`, `AnytmQuizStdPage.do`)를 담아 둔다. 원래 KLAS Helper는 KLAS 페이지 함수 `goLctrumBoard(페이지, 학기, 과목 코드)`로 이동했다. 이동 방법은 KLAS 탭을 만들 때 정한다.

### 학기 선택 (2026-11-06, #22)

과목 목록은 들은 학기를 최근 순으로 준다. 수강 신청 기간에는 아직 시작하지 않은 다음 학기가 맨 앞에 올 수 있으므로, `utils/klas/semester.ts`의 `pickCurrentSemester`가 한국 날짜로 거른 뒤 가장 최근 학기를 고른다.

| 한국 날짜 | 고를 수 있는 가장 늦은 학기 |
|---|---|
| 1~2월 | 전년도 겨울 계절학기 (`<전년도>,4`) |
| 3~6월 | 1학기 |
| 7~8월 | 여름 계절학기 (`<연도>,3`) |
| 9~12월 | 2학기 |

- 계절학기는 정규 학기가 끝나기 전(6월 말, 12월 말)에 시작하지만, 정규 학기의 기말 마감을 놓치지 않도록 그 달 끝까지 정규 학기를 고른다. 그래서 12월 말에 시작한 겨울 계절학기 마감은 1월부터 보인다.
- 휴학 등으로 이번 학기가 없으면 들은 학기 중 가장 최근 학기를 고른다. 정상 응답에서 고를 학기가 없으면 빈 결과를 표시한다. 지원하지 않는 학기 코드가 있으면 과목 목록 응답을 형식 오류로 처리하고 직전 마감 캐시를 유지한다 (#64).
